## 1. Паспорт и бизнес-обоснование

| Параметр | Описание |
|---|---|
| **Бизнес-проблема** | В пиковый сезон распределения 250+ студентов координатор практики ФИТ ЕНУ тратит до 120 мин/день на разбор однотипных сообщений студентов в чатах/почте (на русском, казахском и смешанном языках). |
| **Предлагаемое ИИ-решение** | Интеллектуальный триаж-классификатор обращений по 5 категориям (`CONTRACT_SIGN`, `STATUS_TRACK`, `COMPANY_BIN`, `SCAN_UPLOAD`, `ESCALATE_COMPLEX`) с мгновенной выдачей релевантной подсказки/ссылки студенту и маршрутизацией сложных кейсов в очередь деканата. |
| **Бизнес-метрика (Outcome)** | Снижение времени первичной сортировки и ответа на типовые вопросы с **120 мин/день до ≤ 15 мин/день** (-87.5%); доля самообслуживания по типовым вопросам ≥ 75%. |
| **Метрика качества модели** | `Accuracy ≥ 0.88`, `Macro-F1 ≥ 0.85` на двуязычном (RU/KZ/mixed) golden-наборе из 36 примеров; **`Recall(ESCALATE_COMPLEX) = 1.00`** (запрещен пропуск сложных кейсов). |
| **Базовые решения без ИИ (Baselines)** | 1) Rule-Based Keyword Matcher (`Accuracy = 0.750`, `Macro-F1 = 0.728`, `0.003 мс`, $0);<br/>2) TF-IDF char n-grams + LinearSVC (`Accuracy = 0.417`, `Macro-F1 = 0.358`). |
| **Критерий приемки (DoD)** | `Macro-F1 ≥ 0.85`, прирост ≥ +10 п.п. к лучшему baseline, `Recall(ESCALATE_COMPLEX) ≥ 0.95`, бюджет ≤ $10/мес. |

## 2. Результаты реального эксперимента (Evals)

- **Тестируемая модель:** Открытая модель `GPT-OSS 20B` (`openai-fast`, `temperature=0`, `seed=42`).
- **Набор оценки:** [`evals/dataset.jsonl`](../../evals/dataset.jsonl) (36 самостоятельно составленных примеров: 18 RU, 15 KZ, 3 mixed).
- **Токенизация (`tiktoken cl100k_base`):** System prompt = **697 токенов**, средний запрос студента = **67.7 токена**, итого вход = **764.7 токена**, выход = **2.8 токена**.
- **Фактический результат LLM:**
  - **`Accuracy` = 0.917 (33/36)**
  - **`Macro-F1` = 0.905** (прирост **+17.7 п.п.** к лучшему baseline)
  - **`Recall(ESCALATE_COMPLEX)` = 1.00 (6/6)**, `F1(CONTRACT_SIGN) = 1.00`, `F1(SCAN_UPLOAD) = 1.00`.

## 3. Карточка рисков и Governance (NIST AI RMF / Закон РК № 94-V)

| Категория риска | Описание риска | Последствия ошибки модели | Человек в контуре (HITL) и митигация | Прозрачность и передача данных |
|---|---|---|---|---|
| **Утечка ПДн во внешний API** (Закон РК № 94-V) | Студент пишет в обращении свой ИИН, ФИО и телефон. | Передача ПДн на серверы зарубежного провайдера API. | Обязательный локальный **PII-Redactor** (regex вырезает 12-значные ИИН/БИН, телефоны и email до отправки в LLM, заменяя на `<IIN>`, `<PHONE>`). | Пользователю запрещено вводить пароль; во внешний API уходит только обезличенный текст. |
| **Пропуск критического кейса** | Сложный конфликт или больничный попадет в типовой автоответ. | Потеря срока студентом, жалоба в деканат. | При низкой уверенности или сбое срабатывает дефолтная эскалация к человеку + кнопка «Не помогло — передать координатору». Все приказы/решения утверждает только человек. | Дисклеймер в интерфейсе: *«Предварительная подсказка ИИ. Окончательное решение принимает координатор ФИТ ЕНУ»*. |
| **Недоступность внешнего API / Rate Limit** | Превышение квоты (HTTP 429/402) или сбой сети. | Отказ виджета поддержки в день дедлайна. | Таймаут 3 сек + **Circuit Breaker** с мгновенным фоллбэком на встроенный локальный **Rule-Based Baseline** (0.003 мс, 75% точности). | Логирование каждого сбоя и фоллбэка в аудит-лог для анализа качества. |
| **Дрейф промпта и галлюцинации** | Модель выдает несуществующие категории или меняет ответы. | Поломка JSON-парсера. | Strict JSON parsing + валидация по Enum допустимых категорий + автопрогон 36 golden-тестов в CI перед изменением промпта. | Версионирование `SYSTEM_PROMPT` в Git. |
