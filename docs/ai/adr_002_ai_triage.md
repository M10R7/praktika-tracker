# ADR-002: Внедрение ИИ-классификатора обращений («AI Practice Triage») в Release 2.0

**Статус:** Принято (Approved for Release 2.0 with Guardrails)  
**Дата:** 17 ноября 2026 г.  
**Автор:** Сәбитов Азамат (гр. АЖ-47, Solo PM & Developer)  
**Проект:** «Практика-Трекер» (ФИТ ЕНУ им. Л.Н. Гумилева, г. Астана)  

---

## 1. Контекст (Context)
После сдачи MVP 1.0 системы «Практика-Трекер» (автоматизация заявок, проверки БИН/ИИН, генерации договоров № 107 и сводных приказов) следующей приоритетной точкой роста для Release 2.0 является снижение операционной нагрузки на координатора практики в период массового приема заявлений (250+ студентов на ФИТ и потенциал масштабирования 10x на весь ЕНУ).

В рамках предпроектного исследования (Feasibility Study / CRISP-ML(Q)) рассмотрены три архитектурных варианта реализации классификации и первичной маршрутизации студенческих обращений:
1. **Вариант А (Без ИИ):** Оставить только Rule-Based Keyword Matcher / FAQ.
2. **Вариант Б (Cloud LLM API с Guardrails):** Интеграция легкой коммерческой/открытой LLM по API (`gpt-4o-mini` / `gemini-2.5-flash`) с обязательным локальным PII-фильтром и фоллбэком на Rule-Based.
3. **Вариант В (Self-Hosted GPU):** Развертывание собственной открытой модели (`Qwen2.5-7B` / `GPT-OSS-20B`) на арендованном GPU-сервере (NVIDIA L4, 24GB VRAM).

---

## 2. Рассмотренные факты (Evidence & Trade-offs)

1. **Качество (Evals на 36 примерах RU/KZ/mixed):**
   - Вариант А (`Rules/Regex`): `Accuracy = 0.750`, `Macro-F1 = 0.728` — не справляется со смешанной казахско-русской речью и сложными контекстными вопросами.
   - Классический ML (`TF-IDF + LinearSVC`): `Accuracy = 0.417`, `Macro-F1 = 0.358` — неработоспособен без большого размеченного корпуса.
   - LLM (`GPT-OSS 20B`): **`Accuracy = 0.917`**, **`Macro-F1 = 0.905`**, **`Recall(ESCALATE_COMPLEX) = 1.00`** — уверенно проходит порог приемки ($\ge 0.85$).

2. **Экономика (по замерам `tiktoken cl100k_base` = 764.7 in / 5 out токенов):**
   - Масштаб ФИТ ЕНУ (1 500 запр./мес): `gpt-4o-mini` стоит **$0.18/мес** (~90 ₸); даже при 10x масштабе всего университета (15 000 запр./мес) — **$1.77/мес** (или $5.63/мес в режиме RAG с генерацией черновика).
   - Вариант В (Self-Hosted GPU NVIDIA L4): стоит **$160/мес** (Vast.ai) – **$321/мес** (RunPod Secure). Точка окупаемости наступает только при **426 667 – 1 359 348 запросов/мес** — это в 28–900 раз превышает реальную нагрузку всего вуза.

3. **Безопасность и комплаенс (Закон РК № 94-V):**
   - Передача сырых ФИО и ИИН во внешний API недопустима. Локальный детерминированный `PII-Redactor` до вызова API заменяет ИИН, БИН, телефоны и email на плейсхолдеры (`<IIN>`, `<PHONE>`), не влияя на точность классификации сути вопроса.

---

## 3. Принятое решение (Decision)

**ДЕЛАЕМ в Release 2.0 по Варианту Б (Cloud LLM API + локальный PII-Redactor + Rule-Based Fallback).**  
От Варианта В (**Self-Hosted GPU**) **ОТКАЗЫВАЕМСЯ** как от экономически убыточного на текущем и 10x масштабах (решение о пересмотре принимается только при превышении порога > 150 000 запросов/мес).

---

## 4. Последствия и план доработки MVP (Consequences for Praktika-Tracker v2.0)
При интеграции модуля в существующий кодовый стек FastAPI (`praktika-tracker`) необходимо реализовать:
1. Сервис `src/services/ai_triage.py`:
   - pre-flight очистка ПДн (regex redaction для 12-значных ИИН/БИН, номеров `+7...` и email);
   - клиент OpenAI-compatible API с таймаутом `3.0s`;
   - мгновенный Fallback на `rule_based_baseline` при таймауте/ошибке сети.
2. Эндпоинт `POST /api/v1/support/triage` и виджет подсказок на страницах `/apply` и `/tracker` с обязательной маркировкой ИИ-подсказки и кнопкой эскалации координатору.
3. Интеграция `scripts/run_lz12_eval.py` в GitHub Actions для защиты от регрессии промпта (Quality Gate при изменении `SYSTEM_PROMPT`).
