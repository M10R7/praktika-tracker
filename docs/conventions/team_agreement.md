# Командный регламент и соглашение о качестве (Team Working Agreement)

## 1. Критерии готовности к разработке (Definition of Ready - DoR)
Задача берется в спринт (In Progress) только если:
1. Оформлена по соответствующему шаблону ([US], [BUG], [TECH]).
2. Четко сформулирована бизнес-ценность и цель.
3. Описаны критерии приемки в формате Given-When-Then.
4. Отсутствуют внешние блокирующие зависимости.
5. Произведена оценка в Story Points командой.

## 2. Критерии готовности функционала (Definition of Done - DoD)
Задача считается выполненной (Done) только если:
1. Код проверен линтером (Flake8 / Black), замечания отсутствуют.
2. Написаны модульные тесты для новой логики, покрытие ключевых сценариев.
3. Все автотесты проекта проходят успешно.
4. Ветка синхронизирована с базовой, конфликты слияния разрешены.
5. Обновлена документация и спецификация API при необходимости.
6. Получен минимум 1 аппрув при Code Review в Pull Request.

## 3. Каденция встреч (Agile Cadence)
- **Daily Standup (15 минут):** Вторник и четверг в 10:00 (что сделано, что в планах, какие блокеры).
- **Sprint Planning (Планирование спринта):** Раз в 2 недели по понедельникам.
- **Sprint Review / Demo (Демонстрация):** В конце 2-й недели спринта в пятницу.
- **Retrospective (Ретроспектива):** Сразу после демо (30 минут).
