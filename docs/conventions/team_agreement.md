# Командалық регламент және сапа келісімі (Team Working Agreement)

## 1. Тапсырманы орындауға дайындық критерийі (Definition of Ready - DoR)
Тапсырманы әзірлеуге (In Progress) алу үшін ол мына талаптарға сай болуы тиіс:
1. Тапсырма тиісті шаблон бойынша толтырылған ([US], [BUG] немесе [TECH]).
2. Бизнес-құндылығы мен мақсаты айқын жазылған.
3. Қабылдау критерийлері (Acceptance Criteria) Given-When-Then түрінде сипатталған.
4. Қажетті сыртқы байланыстары мен тәуелділіктері шешілген (блокталмаған).
5. Командамен бағаланған (Story Points берілген).

## 2. Тапсырманың толық орындалу критерийі (Definition of Done - DoD)
Тапсырма «Done» (Дайын) күйіне өтуі үшін:
1. Код таза жазылған, линтер (Flake8 / ESLint) ескертулері жоқ.
2. Негізгі сценарийлер бойынша Unit / Integration тесттер жазылған және сәтті өткен.
3. API спецификациясы мен жүйелік құжаттама жаңартылған.
4. Негізгі бұтақпен (develop/main) қақтығыстар (conflicts) шешілген.
5. Команда мүшесі кодты тексеріп, Pull Request-ке рұқсат (LGTM / Approved) берген.
6. Локалды немесе стендтік ортада демо-көрсетілім жасалып, тексерілген.

## 3. Командалық кездесулер ырғағы (Agile Cadence)
- **Daily Standup (Күнделікті 15 минут):** Сейсенбі және бейсенбі күндері сағат 10:00-де (кеше не істедім, бүгін не істеймін, қандай кедергі бар).
- **Sprint Planning (Спринтті жоспарлау):** Әр 2 апта сайын дүйсенбіде (бэклогты бағалау және спринт мақсатын бекіту).
- **Sprint Review & Demo (Демо көрсетілім):** Спринттің соңғы жұмасында (тапсырыс беруші мен оқытушыға көрсету).
- **Retrospective (Ретроспектива):** Демодан кейін 30 минут (нені жақсарту керек, қандай қателер болды).
