# Регламент индивидуальной разработки и качества (Solo Developer Agreement)

## 1. Критерии готовности задачи к разработке (Definition of Ready - DoR)
Задача берется в работу (In Progress) только если:
1. Оформлена по шаблону ([US], [BUG], [TECH]).
2. Четко сформулирована бизнес-цель и сценарий Given-When-Then.
3. Понятен ожидаемый результат (входные и выходные данные).
4. Оценена трудоемкость в часах или Story Points.

## 2. Критерии завершенности задачи (Definition of Done - DoD)
В условиях соло-разработки (без второго рецензента) качество гарантируется техническим регламентом:
1. Код проверен линтером (Flake8 / Black), предупреждения устранены.
2. Написаны модульные тесты для новой бизнес-логики (pytest), все тесты проходят.
3. Проведена процедура самостоятельного ревью (Self-Review) перед слиянием PR: проверка по диффу, отсутствие временных логов и отладочных данных.
4. Ветка синхронизирована с основной, конфликты отсутствуют.
5. Изменения задокументированы в спецификации или README.

## 3. Ритм работы и синхронизация со стейкхолдерами
- **Личный ритм:** ежедневный контроль личного WIP-лимита (строго 1 задача в работе).
- **Синхронизация со стейкхолдерами:** демонстрация инкремента координатору практики и преподавателю раз в 2 недели по окончании спринта.
