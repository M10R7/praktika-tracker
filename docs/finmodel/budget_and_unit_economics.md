### 2. Расчёт стоимости на одного пользователя в месяц (Unit Cost)

Базовый объём активных пользователей системы составляет **$N = 255$ человек** (250 студентов выпускного потока ФИТ + 3 координатора кафедр + 2 специалиста деканата).

1. **Эксплуатационная себестоимость (на базе OPEX)**:
   $$\text{Cost per User (OPEX)} = \frac{\text{Годовой OPEX}}{12 \times N} = \frac{105\,500 \text{ KZT}}{12 \times 255} = \frac{105\,500}{3\,060} \approx \mathbf{34.48 \text{ KZT в месяц}} \quad (\mathbf{413.73 \text{ KZT в год}}).$$

2. **Полная себестоимость первого года с учётом инвестиций в разработку (CAPEX + OPEX)**:
   $$\text{Full Cost per User (Year 1)} = \frac{\text{CAPEX} + \text{OPEX}}{12 \times N} = \frac{410\,000 + 105\,500}{3\,060} = \frac{515\,500}{3\,060} \approx \mathbf{168.46 \text{ KZT в месяц}} \quad (\mathbf{2\,021.57 \text{ KZT в год}}).$$

3. **Средняя приведенная себестоимость на 3-летнем горизонте (амортизация разработки на 36 месяцев)**:
   $$\text{TCO}_{3y} = 410\,000 + (105\,500 \times 3) = 410\,000 + 316\,500 = 726\,500 \text{ KZT}.$$
   $$\text{Cost per User (3 Years)} = \frac{726\,500 \text{ KZT}}{36 \times 255} = \frac{726\,500}{9\,180} \approx \mathbf{79.14 \text{ KZT в месяц}} \quad (\mathbf{949.67 \text{ KZT в год}}).$$

### 3. Анализ юнит-экономики и точка безубыточности (Break-Even Analysis)

#### 3.1. Структура юнита и генерируемая ценность
В качестве основного юнита принимается **один студент**, проходящий кампанию распределения на практику.

* **Прямая экономия рабочего времени координатора**:
  * Ручной процесс: приём бумажных заявлений, ручная проверка реквизитов, телефонные звонки, сверка БИН через eGov, повторное перепечатывание договоров из-за опечаток $\rightarrow$ в среднем **40 минут** на 1 студента;
  * С системой «Практика-Трекер»: мгновенная подача заявки, автопроверка БИН по алгоритму КГД, координатор тратит **3 минуты** на клик «Одобрить» и автогенерацию договора;
  * Высвобождение времени: **37 минут** на одного студента;
  * Денежный эквивалент (при ставке преподавателя/координатора 2 500 KZT/час):
    $$\text{Экономия времени} = \frac{37}{60} \times 2\,500 \approx \mathbf{1\,542 \text{ KZT на студента}}.$$
* **Экономия расходных материалов**: бумага А4 (3 экземпляра договора + лист приказа), тонер лазерного картриджа, канцелярские папки $\approx \mathbf{250 \text{ KZT на студента}}$.
* **Итого прямая ценность юнита ($B_{\text{unit}}$)**:
  $$B_{\text{unit}} = 1\,542 + 250 = \mathbf{1\,792 \text{ KZT на одного студента}}.$$

#### 3.2. Годовая прямая выгода и косвенные эффекты
* При базовом потоке $N = 250$ студентов годовая прямая экономия составляет:
  $$\text{Прямая выгода} = 250 \times 1\,792 = \mathbf{448\,000 \text{ KZT/год}}.$$
* Косвенная выгода: исключение риска задержки выхода приказа деканата (предотвращение административных штрафов, выговоров и срыва графика учебного процесса) $\approx \mathbf{80\,000 \text{ KZT/год}}$.
* **Совокупная годовая ценность (Benefits)**: $448\,000 + 80\,000 = \mathbf{528\,000 \text{ KZT/год}}$.

#### 3.3. Расчёт точки безубыточности (Break-Even Point)
1. **Точка покрытия ежегодных эксплуатационных расходов (OPEX-сходимость)**:
   $$N_{\text{BEP (OPEX)}} = \frac{\text{Годовой OPEX}}{B_{\text{unit}}} = \frac{105\,500 \text{ KZT}}{1\,792 \text{ KZT}} \approx \mathbf{59 \text{ студентов}}.$$
   *Вывод*: для полной компенсации серверных и эксплуатационных затрат достаточно обработать всего **59 заявок** (менее двух академических групп).

2. **Точка полной окупаемости за 1-й год (с учётом инвестиций в разработку CAPEX)**:
   $$N_{\text{BEP (Full 1 Year)}} = \frac{\text{CAPEX} + \text{OPEX}}{B_{\text{unit}} + \text{Косвенная выгода/студент}} = \frac{515\,500 \text{ KZT}}{1\,792 + 320 \text{ KZT}} = \frac{515\,500}{2\,112} \approx \mathbf{244 \text{ студента}}.$$
   *Вывод*: при текущем размере потока ФИТ в **250 студентов** проект полностью окупает затраты на собственную разработку уже **в первый же год эксплуатации** ($250 > 244$).

3. Со 2-го года проект генерирует чистый экономический эффект для факультета в размере:
   $$\text{Чистая выгода (Год 2)} = 528\,000 - 105\,500 = \mathbf{+422\,500 \text{ KZT ежегодно}}.$$

### 4. Трёхлетний сравнительный анализ вариантов размещения (3-Year TCO)

Сравнение проводится по трём альтернативным архитектурным стратегиям хостинга в соответствии с заданием силлабуса.

#### 4.1. Описание сравниваемых вариантов
* **Вариант 1 (Public Cloud — AWS / Azure / Yandex Cloud)**:
  * Публичное облако: инстанс 2 vCPU, 4GB RAM, 50GB SSD NVMe ($\approx \$32$/мес);
  * Managed Service for PostgreSQL (1 vCPU, 2GB RAM, 20GB SSD) $\approx \$28$/мес;
  * S3 Object Storage + исходящий сетевой трафик (Egress traffic) $\approx \$5$/мес;
  * Совокупные затраты в месяц: $\approx \$65 \times 490 \text{ KZT} \approx 31\,850$ KZT/мес (382 200 KZT/год).
* **Вариант 2 (On-Premises — серверное оборудование университета)**:
  * Покупка 1U стоечного сервера начального уровня (2×NVMe Enterprise, 32GB RAM, RAID) = 650 000 KZT;
  * ИБП онлайн двойного преобразования (UPS 1.5 kVA) = 120 000 KZT;
  * Эксплуатация: электроэнергия (300 Вт круглосуточно $\approx 216$ кВт·ч/мес $\times 28$ KZT = 6 048 KZT/мес = 72 576 KZT/год), выделенный IP и порт вуза (25 000 KZT/год), замена комплектующих и ТО (50 000 KZT/год) $\rightarrow$ OPEX = 147 576 KZT/год.
* **Вариант 3 (Open Source стек на арендованном Cloud VPS в РК — PS.kz / Выбор проекта)**:
  * Аренда виртуального сервера Cloud VPS (PS.kz, Алматы, Tier III): 2 vCPU, 4GB RAM, 50GB NVMe = 5 000 KZT/мес (60 000 KZT/год);
  * Доменное имя `.KZ` = 3 500 KZT/год;
  * S3 Object Storage для бэкапов = 12 000 KZT/год;
  * Открытый стек: Ubuntu 22.04, Docker Compose, PostgreSQL 15, FastAPI, Nginx, Let's Encrypt SSL (0 KZT за лицензии);
  * Поддержка и непредвиденный фонд = 30 000 KZT/год $\rightarrow$ OPEX = 105 500 KZT/год.

#### 4.3. Обоснование выбора архитектурного решения
**Выбран Вариант 3 (Open Source стек на Cloud VPS PS.kz)** по следующим критическим критериям:
1. **Экономическая эффективность**: трёхлетний TCO составляет **396 500 KZT**, что более чем в **3.1 раза дешевле** собственной On-Premises инфраструктуры и в **3.3 раза дешевле** публичного облака;
2. **Юридическая чистота (Compliance)**: физическое нахождение дата-центра в Республике Казахстан (г. Алматы) исключает юридические риски хранения персональных данных студентов (ИИН, телефоны) за рубежом;
3. **Бесшовная интеграция с MVP**: стек Docker Compose + FastAPI + PostgreSQL 15 полностью подготовлен к локальной разработке и без изменений разворачивается на выбранном VPS одной командой `docker compose up -d`.
